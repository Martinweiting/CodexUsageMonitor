## 1. 產品目的與決策

讓使用者回答六個問題：用了多少、何時使用、用在哪些任務、哪些來源占比較高、近期如何變化，以及數字是否完整可信。

「全部列出來」採本產品目的內的完整候選清單，不將所有候選同時塞進首頁。以下 60 項分為 P0、P1、P2；P0／P1 是預定實作範圍，P2 是有明確資料門檻的條件式範圍。P2 未達門檻時只交付不支援狀態與原因，不用推測補值。本次不啟動任何階段的功能實作。

維持本機、唯讀、不保留對話內容的既有邊界。所有統計標示「本機紀錄」，不宣稱是官方帳戶總量、跨裝置總量或所有已刪除紀錄的總和。只使用現有專案已讀取的本機來源；本 SPEC 不要求新增 API key、網路服務或套件。

## 4. 統計口徑與計算規則

### 4.1 日期與比較

1. 所有儲存時間維持 UTC；顯示與日期分組採 Windows 目前本地時區。清楚顯示時區名稱／偏移，不能固定假設 UTC+8。
2. 區間使用 `[start, end)`，包含開始、排除結束；使用者選擇結束日則轉為下一日本地 00:00。今日截止目前最後可用快照時間；禁止選未來日期。
3. 近 7／30 日包含今日及前 6／29 個日曆日；本週星期一開始，本月由 1 日開始。「全部紀錄」從第一筆可讀紀錄到快照時間，不標示前期比較。
4. 完整日期區間與緊鄰的同日曆日數完整區間相比；含今日的未完整區間，預設與前一等長區間的相同本地時刻進度相比。DST 遇無效時刻向後取第一個有效時刻，重複時刻採較早時點，並在詳情列出實際 UTC 起訖。
5. 目前＝120、前期＝100，差值 +20、增幅 +20%；前期為 0 且目前大於 0 顯示「前期為 0」，不得顯示無限大。雙方皆 0 顯示「無變化」；任何一方資料未知則不顯示增減百分比。
6. 日期快取須在跨日、時區變更與系統時間調整後重新分組。DST 日期可有 23／25 小時，重複小時以偏移區分，不強行壓成 24 桶。
7. 無可讀資料、尚未涵蓋、已讀但沒有紀錄事件是不同狀態。無活動以「未記錄活動」表示，不宣稱使用者當天完全沒有使用。

「涵蓋」只表示已讀到的本機紀錄範圍，不能證明歷史檔案從未被刪除。P0 若只能取得全域 partial，所有涉及該快照的日期都保守標示可能不完整；P1 取得可定位的診斷證據後才縮小影響日期，不以第一筆／最後一筆時間推定中間資料完整。

### 4.2 Token 與可信度

1. 沿用 session 內累積計數的增量算法，先保留區間前的 predecessor 再過濾日期；不能先截日期才做差，否則會把歷史累積算到第一天。
2. 範例：23:59 累積 100、00:01 累積 150，次日分配 50；同值再報一次分配 0。計數器重設沿用既有區段規則，新增診斷標記而非悄悄修改既有總量算法。
3. 第一筆可見累積值缺少 predecessor 時，保留既有首筆計入的相容行為，但標示「含首筆累積值，時間分布可能不完整」。不能把這段數值當成精確在該秒發生的消耗。
4. `total_tokens` 是總量。cached／cache-write 是輸入分項，reasoning 是輸出分項，不能再加回總量；也不能假設 cached 與 cache-write 互斥。
5. 輸入與輸出占比以兩者和為分母，旁註原始 total。兩者和與 total 不一致時顯示差異，不強行更改來源數字。
6. 快取比例＝cached / input；推理比例＝reasoning / output。分母 0 或缺漏顯示 `—`；子項大於母項顯示「分項不一致」，不截成 100% 隱藏問題。
7. 非快取輸入差額＝input − cached，僅在兩欄均有效且 input ≥ cached 時計算；cache-write 另列，不再扣除一次。
8. 現有數值模型把部分缺欄位讀為 0。P1 增加每欄 presence／validity；舊快取沒有 presence 時標示未知並安排重建，不能假造為全部有值。
9. 每一桶保存已知值、缺漏事件數、涵蓋狀態。部分可用仍可看已知小計，但比例與跨期比較必須附限定，不把缺資料當成節省。
10. 去重先於所有聚合；日圖、總卡、任務表及匯出使用同一份增量結果。fork／別名／篩選不改寫來源歸屬。所有數字 64-bit 並檢查飽和；圖表縮放可用浮點，但原始數值不可丟失精度。

### 4.3 任務、回合與平均

- 保留六張既有摘要的「今日」與「本機累計」入口；期間選擇不使本機任務總數偷偷變成活躍任務。卡片標題必須包含口徑。
- 本期活躍任務＝本期至少有一筆頂層使用者回合的唯一 session ID，維持既有 todayTaskCount 語意。只有 Token 的 session 另列 A30。
- 任務／回合排除已確認非頂層來源；Token 總量包含所有來源。未明來源維持舊規則的相容總計，但來源圖必須另列「未辨識」，並說明可能包含推定頂層。
- 任務表可切換「頂層任務」／「所有 session」；後者不得仍標示為頂層任務數。session index 只有 ID 沒事件者只屬本機任務清單，不憑 index 更新時間產生活躍紀錄。
- 每活躍任務平均值只聚合該活躍頂層 session 集合的 Token／回合。頂層 Token／回合比值只使用頂層資料，不將子代理 Token 混入後聲稱為單回合成本。
- 新任務以 session 建立時間判定；回訪任務為建立早於區間開始且本期有使用者回合；建立時間未知者另列。A30 可與新／舊 session 重疊，不能把所有卡片相加當總任務數。
- 去重使用者事件沿用現行 session＋時間鍵並標示其限制。沒有穩定 turn ID 前，A51／A53／A54／A59 不可啟用；新版來源遷移須有新舊事件交叉去重 fixture。
- 任務預設 `任務 #短代號`，短代號碰撞時延長。完整 session ID 不預設顯示或匯出；自訂別名只由使用者輸入，不讀 `session_index` 的文字標題。

### 4.4 趨勢、摘要與參考值

- 活動日＝至少一筆使用者回合或正 Token 增量；連續紀錄中遇已掃描無事件日中斷，遇涵蓋未知日則顯示不完整，不能跨過缺漏宣稱紀錄。
- 7 日均線使用該日及前 6 個日曆日；零事件日可計 0，未知日不可當 0。未滿／未完整 7 天顯示不完整均線狀態。
- A17 異常規則初版：至少 7 個有效完整歷史日，當日已知 total 超過前 28 個完整日之有效日中位數 2 倍；中位數為 0 或不足樣本則不判定。標籤「高於近期基準」，不稱為異常行為或錯誤。
- A18 固定模板只引用畫面相同篩選、快照、日期與已知數字；有 partial 時首句附「依已讀取紀錄」。沒有資料則不生成摘要。
- A44／A45 只比較今日全部本機來源 Token 與使用者設定的正整數參考值；跨日重算，超過後不截斷實際值。切換篩選不改變門檻母體；提示只在頁內出現。
- A52 若通過資料門檻，初版估計為事件後 60 秒視窗的時間聯集、按期間裁切；不同 session 重疊只算一次，標示「紀錄活動時間估計」，不使用首末時間相減當工作時間。

## 5. 頁面結構與操作規格

### 5.1 小工具活動首頁

維持目前面板級距與玻璃風格，不因內容多就持續增加高度。順序如下：

1. 既有「額度／活動」頁籤。
2. 期間選擇器＋「本機紀錄」標示；自訂區間以精簡日期文字顯示。
3. 期間 Token／活躍任務／回合三卡，下方差值；第二列保留本機累計 Token／任務／回合。預設期間為今日。
4. 一張近期趨勢預覽；預設 7 日 Token 圖，明確標示「近 7 日預覽」，不冒充只含今日。點「查看趨勢」開啟詳情，帶入其 7 日期間。
5. Token 分類摘要，可開詳情檢查完整數字、子集合與比例。
6. 常駐資料品質狀態列＋「分析詳情」＋現有重新整理。

遠端帳戶資訊移到活動頁內可展開的「遠端帳戶狀態」，保留原本內容與取得狀態；本機期間／任務篩選不影響它，並顯示遠端資料自己的更新時間。既有重新整理維持同時更新本機／遠端；A39 額外入口明確寫「僅本機」。

### 5.2 活動分析詳情視窗

- 同程序、由使用者明確開啟的原生可調整大小視窗；固定開啟，不因滑鼠離開收合。採單一實例，再次開啟將現有視窗帶到前景。
- 五個分區：「趨勢」「Token」「任務」「資料品質」「偏好」。P2 模型／專案／執行情況在能力達標後於相關分區加入次級頁籤，未支援時提供原因說明。
- 頂部統一期間、來源與重設篩選；任務搜尋與標籤只篩任務清單，除非使用者明確選「以此任務檢視全部分析」。遠端狀態不接受本機篩選。
- 點圖表柱／熱度格帶入日期，再開對應明細；提供清楚返回與清除選取。期間變化時清除已失效的格子選取。
- 表格預設 50 列一頁，可選 25／50／100；排序穩定，相同值依匿名 ID；高 cardinality 圖表 Top 10＋其餘＋未知，總和需一致。
- 單位切換、圖例與提示不得遮住可點擊區域；滑鼠和鍵盤均能開相同數值詳情。工具提示不能是唯一取得數值的方法。
- 切回額度頁再回活動時保留期間；相對期間在每次新快照重新求值。詳情視窗關閉只收起視窗，不關閉小工具。
- 簡單模式只沿用今日 Token／任務摘要，不加入排行或熱度圖；任務模式與懸浮球不增加資訊密度，可由右鍵「活動分析」進入詳情。

### 5.3 點擊與繁體顯示

- 繁體中文是設計與主要驗收語言。中文使用 Iansui，數字／英文依既有 Quantico 分段；萬／億／兆等格式保留，完整整數可檢視與複製。
- 文字語意使用「使用者回合」「本機累計」「未記錄活動」「資料不完整」「前期」，避免「對話數」混用 task／turn。
- 新增按鍵高度至少 32 DIP、主要操作 36 DIP，圖表熱度格可較小但必須有鍵盤／表格替代；文字裁切時保留完整文字入口。
- 所有新控制項優先命中，包含已選取頁籤，不能落入面板拖曳。捲動內容座標須轉換後再命中；圖表選取／滑桿拖曳要正確捕捉及取消。
- 滑鼠放開於按鍵外取消新按鍵動作；失去捕捉、Esc、Alt+Tab 不誤觸發。背景掃描或快照刷新不移動使用者正在操作的按鍵。
- 所有新增原生選單／日期選擇／tooltip 不得重啟離開訊息迴圈。沿用本次 click-interaction-recovery 的視窗遮蔽與選單保護。
- 順序 Tab／Shift+Tab、Enter／Space 啟動、Esc 關閉提示／詳情、方向鍵巡覽圖表；焦點外框需在 0–80% 透明度及明暗主題均可辨識。
- 新資料與畫面狀態變化提供可讀狀態文字；若現有自繪視窗未暴露 UI Automation，P0 必須補齊新增控制項的 name／role／state，不能僅靠截圖定位即宣稱無障礙完成。

## 6. 資料模型與工程拆分

以下是未來實作建議的型別／模組，現在並不存在。

| 模組 | 職責 |
| --- | --- |
| `LocalUsageStats.*` | 增量掃描、欄位有效性、去重與資料來源診斷；不處理 UI 排版 |
| `ActivityAnalytics.*` | 純聚合：`ActivityQuery`、日期桶、比較、比例、任務排行、規則摘要 |
| `ActivityPresentation.*` | 卡片文字、圖表／表格模型、命中與焦點幾何；避免把計算全部放入 `PaintContent` |
| `ActivityDetailsWindow.*` | 詳情生命週期、原生控制項、鍵盤與無障礙、分頁與圖表繪製 |
| `ActivityExport.*` | 從同一不可變結果輸出 CSV／JSON，包含 schema version／期間／口徑 |

`ActivityQuery` 至少含：相對期間種類或固定 UTC 起訖、本地時區規則識別、來源篩選、可選 session ID、指標、分組粒度。所有 async query 帶 generation ID，較舊請求晚回來時不得覆蓋新期間。

`ActivityResult` 至少含：snapshot generation、實際區間、quality、六類 Token 與有效性、活躍任務集合／數量、使用者回合、比較結果、圖表桶、分頁任務表、資料涵蓋與索引時間。缺少欄位使用 optional／狀態列舉，不能用一個 0 同時代表無資料與真零。

事件層增加可選的 originKind 與欄位有效性；保留 legacyTopLevel 推定以兼容舊總量。P2 才增加可選 model／project／turn／parent 等證據欄位，每個欄位帶來源 schema 與可靠性。歸屬不明的 Token 必須留在未知桶，不能按最接近的 metadata 猜測。

### 6.1 快取與搬移

- 需要新增欄位時使用版本化 v2 索引；v1 先唯讀載入作過渡快照，在背景從仍存在的原始檔重建 v2，不在 v1 缺漏欄位上填 0。
- 同目錄暫存＋原子替換，成功前不覆寫有效快取。取消、磁碟滿、格式錯誤時繼續保留舊快照並標示狀態；保留一份可回復的上一版快取。
- 原始檔不存在的 v1 歷史只能標示為舊快取紀錄；新維度為未知，不宣稱已回填。UI 可同時列「可重新驗證」與「僅舊快取」涵蓋。
- 歸檔搬移、同名不同檔、fork、截斷、counter reset、未完成尾列需延續 fixture；checkpoint 增加可辨識檔案替換的 identity／fingerprint，不能只憑大小與檔名認為同一份資料。
- 唯讀邊界允許建立本工具索引、別名與偏好；不修改 Codex session、session index、auth 或任何對話。別名與標籤放獨立版本化偏好檔，刪除別名不刪紀錄。
- 不把 UI 偏好／掃描時間當成活動事件。不得只保留每日總量就宣稱還能支援小時、任務或模型回溯。

### 6.2 非阻塞與容量

- 初始掃描、聚合、快取與匯出全部在受控 worker 執行；UI thread 不掃磁碟、不排序大量事件、不 join 尚未完成的查詢。
- 延續 15 秒本機掃描；沒有新增 bytes 時不得重讀 JSONL。只有日期／時區改變時可重新聚合，不能因此重掃全部檔案。
- 現行快取有 64 MiB 上限；P1 必須改成分片或具明確容量策略的版本化索引，超出時不能無限重建。所有淘汰／容量限制須有可見狀態，不能靜默丟失歷史。
- 驗收目標：熱快照切換期間 p95 ≤200 ms；互動不因掃描阻塞超過 100 ms；有快取時 1 秒內顯示舊快照；取消查詢 500 ms 內進入取消狀態。以固定機器、資料量與量測方法記錄，未達即調整，不把目標當成既有結果。
- 壓力 fixture 至少 100 萬 Token 事件、1 萬 session；報告冷掃描耗時、熱查詢、記憶體峰值與 cache 大小。圖表採桶與取樣呈現，但 tooltip／匯出使用原始整數。

## 7. 匯出與資料控制

1. 使用者按「匯出」，先選目前摘要／日分布／任務表／資料品質，以及 CSV 或 JSON，再以本地另存對話框選目的地；取消不寫檔。
2. 預覽列出範圍、列數、欄位、是否包含使用者別名／標籤。預設匿名 ID，不含帳號 email、完整 session ID、專案路徑、提示、回覆、reasoning、工具輸出。
3. JSON 包含 `schemaVersion`、`generatedAt`、UTC 起訖、本地時區、query、definitionVersion、quality、原始計數；64-bit 數值以十進位字串保存，避免 JavaScript number 精度損失。
4. CSV 採 UTF-8 BOM、穩定欄名、原始十進位整數、標準雙引號 escaping；帶 `= + - @` 等公式起始的使用者文字必須中和。另以欄位保留缺值／品質狀態，不寫成 0。
5. 匯出固定同一 snapshot generation；背景新增資料不使半份檔案來自另一快照。覆寫既有檔案由原生另存確認處理；寫失敗保留來源資料並回報原因。
6. 不新增自動上傳、分享連結或預設把別名帶到匯出。複製只發生在使用者點擊指定數值／摘要時。
